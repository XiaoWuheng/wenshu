# 产品说明

## 产品定位

文枢是独立创作者和小型内容团队的本地优先创作工作空间。它关注从选题到发布之间容易散落的资料、事实判断和素材授权记录。

## 服务对象

- 独立记者、自由撰稿人和新闻编辑；
- 视频创作者、播客制作人及自媒体工作者；
- 需要记录资料出处、访谈、影像和授权的文化工作者；
- 希望保持轻量工作流的小型编辑团队（当前版本仅支持单浏览器、单用户）。

## 要解决的问题

创作常在多个工具间进行：选题在便签，资料在浏览器，稿件在文档，核验与授权靠记忆。文枢把这些内容关联到同一项目，让创作者能快速回查来源、发现未处理事项，并导出可迁移的记录。

## 核心体验原则

1. **先让创作过程可追溯。** 资料、陈述、素材和发布检查之间建立清楚的关系。
2. **工具建议下一步，创作者作决定。** 自动提示不等于事实或权利结论。
3. **默认本地保存。** 对外发送、AI 调用、同步和遥测都必须清晰说明并由用户主动选择。
4. **用户可以带走数据。** 备份、Markdown 稿件和项目包是核心工作流的一部分。
5. **可逐步上手。** 模板、空状态、指南与项目下一步建议帮助用户完成首个项目。

## 当前版本范围

当前产品包含项目管理、创作模板、资料来源、Markdown 稿件、人工事实核验、素材授权记录、发布前检查、全局搜索、本地备份导入导出、GitHub Pages 静态部署，以及可选的自托管 AI 辅助服务。

当前产品不包含云端账号与同步、多人协同、在线文件存储、自动版权判断或自动事实验证。AI 仅在用户配置并运行自托管 Node 服务后可用；界面中的相关说明应持续保持准确。

## 关键任务流程

1. 创建项目或从模板开始。
2. 添加采访、链接、文件出处或个人笔记。
3. 撰写和整理稿件。
4. 对具体事实建立核验项并关联来源。
5. 登记素材来源、使用位置、授权和署名。
6. 按发布渠道完成人工检查。
7. 导出项目包并保留本地备份。

项目总览根据项目资料推荐下一步。推荐用于缩短操作路径，不替用户跳过确认步骤。

## 后续产品方向

### P1：安全、可迁移的数据工作区

增加更清晰的版本备份与恢复、项目归档说明、数据格式文档和本地文件整理能力。

### P2：完善 AI 协作

当前已有服务端代理、OpenAI Responses / 兼容 Chat Completions 调用、逐次发送确认、结果人工采纳和待核验提取。后续应增加服务商连接向导、用量预算提示、可撤销历史、模型评测和更细的团队权限。保持 API 密钥只在服务端，默认不发送用户内容。

### P3：小团队工作流

在身份、权限、冲突处理和审核记录设计完成后，再考虑协作与共享。共享前要明确资料可见范围和敏感内容处理方式。

## 产品完成标准

- README 所述能力在应用中可找到且可实际使用。
- 新用户能够从空工作区建立项目并完成一次基本创作流程。
- 重要数据操作有解释、备份或确认机制。
- 不把 AI 输出、来源关联或用户勾选误称为系统自动核验。
- GitHub Pages 可直接部署，应用无需提交任何密钥。
